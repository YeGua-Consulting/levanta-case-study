# 客户站外露出调研：方法、范围与表述尺度（定向版）

定向版的策略页（`strategy.json`）和结构页（`structure.json`）都要回答“客户现在站外做了什么、还缺什么”。这个判断全靠公开检索，检索范围有限，所以**方法要能复述、结论要能回溯、措辞要留余地但不能软到没有刺痛感**。按下面做，并把过程写进演讲者备注。

## 一、查什么（按伙伴类型逐项查）

| 伙伴类型 | 查法 | 判定依据 |
|---|---|---|
| 内容型 · 垂类媒体与榜单 | 先找出**该品类最有分量的 3–5 个榜单/测评页**（品类词 + best / review / tested，优先 Bob Vila、The Spruce、Family Handyman、People Inc. 旗下、Popular Science、Consumer Reports、Wirecutter 和该品类垂直媒体），然后**整页抓取读全文**，逐个核对产品清单里有没有客户品牌 | 读过全文才能写“榜单内未见”；只看摘要不能写 |
| 内容型 · 媒体评测 | 品牌名 + review / tested / unboxing；品牌名 + 各媒体名 | 抓到页面后记下：媒体、日期、是否标注赞助、是否带联盟链接 |
| 内容型 · 创作者 | 品牌名 + YouTube / TikTok / Instagram；`site:youtube.com 品牌名`；第三方赞助追踪站（如 SponsorRadar）；客户官网的博客/用户故事栏目（常转载创作者视频） | 能说“有创作者评测”；数量和平台覆盖面说不全，用“含…类频道” |
| 买量型 | 品牌名 + 导购榜单站名；Google Ads Transparency Center 按广告主查（淡季 SERP 搜不到广告很正常） | 多数情况写“公开检索未见” |
| 优惠与返利 | 品牌名 + deal / coupon / slickdeals；家居类博客的 Prime Day / 黑五专题 | 区分“主流 Deal 社区有品牌帖”和“博客 Deal 专题” |

工具层面：网页搜索接口每次返回前 15–25 条，不是翻页浏览，所以**每类至少换 2–3 种关键词**；关键页面用抓取工具读全文；无法抓取的站点（部分媒体有反爬）换搜索结果里的镜像或让用户截图。TikTok / Instagram 站内内容、付费广告实投、Amazon 站内 Creator Connections 这类不产生公开页面的合作**查不到**，要在备注里写明“未覆盖”。

## 二、怎么写（尺度）

- **三档措辞**：核对过全文的用肯定句（“Bob Vila 2026 榜单内未见”）；只搜到结果摘要的用“公开检索未见”；没有检索能力的写“未覆盖/无法核实”。页面上**永远不写“没有”“从未”**。
- **点名要具体**：刺痛客户靠的是“这四个榜单你都不在、同类品牌都在”，不是形容词。榜单名要写全，而且只写核过的；竞品名只进备注，页面不点。
- **状态词四档**：✓ 已有 / △ 部分 / — 未见 / ✗ 未进入。“未进入”只用于核过全文的榜单。
- **页脚列范围**：“现状为 ×× 月公开检索结果（逐页核对：…），‘未见’指检索范围内未见。”这样客户说“我们上过 XX”时，答“那是公开检索范围外的，正好聊聊”，不会被动。
- **备注写全**：查询词组、抓取过的页面（标题、日期、作者/是否赞助）、第三方工具结果、未覆盖项。现场被 challenge 时能当场翻出来。

## 三、结构页左图（平台伙伴类型占比）的合规处理

- 这类平台级汇总数据如果**不是公司对外发布的口径**，页面上：不归属到 Levanta（写“联盟渠道样本”），不写精确百分比和席位数（用“一半以上 / 约三成 / 约一成 / 不足一成”，`value_label` 字段），标注“内部分析口径，取整，不含任何单个品牌或伙伴数据”；Levanta 口播时再说。精确值和来源只写在备注。
- 取得负责人批准后可改回精确值和 Levanta 归属。
- 无论哪种版本，页面都不出现其他平台名称，不对客户现用平台作评价；比较只落在“覆盖了哪些类型、还缺哪些”。

## 四、工作量参考

一个客户的完整调研约 10 组查询 + 6–8 个页面全文核对，30–40 分钟。先查榜单页（最有价值、最可核实），再查评测和创作者，Deal 与买量最后。
