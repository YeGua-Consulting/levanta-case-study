# 出单伙伴结构 × 客户覆盖现状页（定向版专用，`structure.json`）

**用途**：客户在比较不同平台、或问“为什么要再加一个平台”时，不做平台对平台的功能比较，而是回答“出单的伙伴结构是什么、你现在覆盖了哪些类型、还缺哪些”。页面左边是 Levanta 平台层面的伙伴类型销售额占比，右边是该客户的覆盖现状与机会点，底部一句话收口。

**数据边界**
- 左图的伙伴类型占比来自对平台伙伴报表的内部分析（近 12 个月前 100 出单伙伴：内容型约 53% / 买量型约 30% / 优惠与返利约 10% / 联盟网络及其他约 7%），**不是公司对外发布的口径**。默认做法：页面不归属 Levanta（写“联盟渠道样本”），只显示取整表述（`value_label`：一半以上 / 约三成 / 约一成 / 不足一成），柱长仍按 `value` 比例绘制，标注“内部分析口径，取整，不含任何单个品牌或伙伴数据”；Levanta 口播时再提。取得负责人批准后，去掉 `value_label` 即显示精确值。数据更新时改 `chart.bars` 与 `chart.note`。
- 右表只写公开可见的客户露出，调研方法、检索范围与措辞尺度见 `client-research.md`：核过全文的榜单用“✗ 未进入”，只有搜索摘要的用“— 未见”，有部分露出用“△ 部分”，查不到的在备注写“未覆盖”；页脚列出核对范围。
- 不出现其他平台的名称，不对客户现用平台做评价；竞品只在备注里提，页面不点名。

**怎么填**：复制 `assets/structure-page-default.json` 为 case 目录的 `structure.json`，替换〔〕。`status_kind` 决定状态词颜色：`yes` 绿 / `no` 红 / `partial` 橙 / `none` 灰。`now` / `next` 可以是数组（每项一行）。`make_case.py` 发现 `structure.json` 自动插入（默认 `insert_after` 5，位于策略页之前；`--no-structure` 跳过）。

**版式**：左面板 500×350（四条横向条形，第一条深绿高亮），右表三列（默认 150 / 240 / 264.4），五行等高；收口色带 50px；页脚两行以内。渲染后检查：条形标签两行内、右表每格三行内、色带单行。

**配套话术**（讲这页时）：先问客户“现在出单前五的伙伴是哪几类”，再对照左图说“平台上 53% 的销售来自内容型伙伴，你已经有创作者这一半，媒体榜单这一半还没有”，然后翻到策略页讲怎么补。不比价格、不比平台功能。
